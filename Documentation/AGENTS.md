# Instructions for Anno 1800 documentation and mod work

- Read README.md, reference/coverage.md and reference/discrepancies.md first, then only the chapters relevant to the task. Answer in the user's language; repository prose is English.
- This folder is the single maintained knowledge base. Follow maintenance.md for reusable findings; do not maintain or synchronize another edition in ModdingWithCodex.
- Before the first game-dependent proposal, implementation decision, code change or dependent test, complete the feature-specific audit in foundations/vanilla-research.md using the user's own current extracted sources. A GUID hit, inventory, historical excerpt or working mod example does not replace the audit. Ask for inaccessible essential files; never invent unknown native contracts.
- A supplied local path is useful only when a tool can actually read it. With GitHub-only access, use public sources for explanations and ask the user to provide required native files for an audit. Never require Serp's PC, notes or private reports.
- Local tools read ignored local.json (or ANNO_DOCUMENTATION_CONFIG). Relative paths resolve against the configuration file's directory. Never copy personal paths from dated provenance into active instructions. Do not commit local configuration, extracted game databases, saves, generated mods or disposable logs.
- Use setup.md and workflow.md directly. No globally installed skills are required. Keep user work in configured workPath and audit/output files in configured outputPath. A configured modsPath is not installation authorization. Custom generated directories within a repository need ignore rules before writing.
- New text files use UTF-8 and CRLF. Preserve existing encoding, structure, names and useful comments. Ask before changing encoding or broadly rewriting an existing mod. Prefer targeted improvements.
- Use author-specific ModIDs and resource paths. New asset IDs require the current 1800 registry and collision checks against Vanilla and relevant mods/dependencies. Documentation grants no author's reserved range to another user.
- Use supported legacy Anno 1800 ModOps; distinguish Anno 117 examples and tools. An empty template is not a completed mod.
- Report source evidence, structural checks, offline loader assertions, game/save observations and multiplayer tests separately. Missing optional tools make related checks unavailable, not passed. Inspect evaluator logs and actual output assertions, not exit status alone.
- Run Git and Lua outside the Windows sandbox through the supported permission route. For a documented xmltest sandbox startup failure, retry the unchanged safe command through that route; do not infer game behavior from a startup crash.
- Check PowerShell quoting and pipelines. Never pipe directly from statement-based foreach; collect results first. Never repurpose HOME or CODEX_HOME. For WindowsApps pwsh CreateProcessAsUserW error 5, retry the unchanged safe call once with escalation; if that also fails, stop and ask.
- If a supplied literal path containing backslash-underscore does not exist, also check the underscore interpretation and disclose a confirmed correction. Do not choose silently between two existing paths.
- Ask when intent is unclear or a real problem has materially different solutions. Necessary questions have no timeout; retain progress and stop dependent work until answered.
- Do not install, overwrite an existing mod, publish, commit, push or send messages unless authorized. A mod-creation request authorizes the local result and appropriate checks, not deployment.
- Documentation validation must be read-only. Preserve dated source hashes, IDs, original test certainty and historical receipts. New corrections link earlier evidence instead of silently rewriting its history.
