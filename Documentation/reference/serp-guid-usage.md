## Allocation workflow

Before assigning a new GUID, run `python -B tools/guid_inventory.py --check NUMBER` from Documentation with `workspacePath` configured in ignored `local.json`, or pass `--workspace PATH`. Exit 0 means no literal occurrence in the scanned scope; exit 1 means occupied, and exit 2 means invalid input or an incomplete metadata check. After allocation, refresh with `python -B tools/guid_inventory.py --write` and review the result. The default command only reports counts and never writes. Check Vanilla and relevant external dependencies separately as required by the normal feature audit.

All occurrences block fresh allocation, including references, comments, disabled files, WIP and old variants. A reference alone is not evidence of an asset definition. Do not recycle such IDs without tracing their ownership. The scanner includes hidden/ignored text sources and bundled copies; it excludes Documentation itself, Git/SVN/cache directories, node_modules, directory symlinks, binary files and archives. Only literal decimal IDs are detected; range comments block their literal endpoints only. Inspect declared subranges, generated/calculated IDs and unextracted archives manually. File-read errors abort the scan. Text extensions and definition heuristics are explicit in the scanner source.

Same-ModID copies and explicitly incompatible pairs are classified separately, following Serp's instruction. Neither classification releases the GUID for a new unrelated asset. Metadata describes possible alternatives, not which version is installed. Other pairs are review candidates, not confirmed runtime collisions: conditional ModOps, intentional patches, inactive branches and alternative packages can explain them. Lexical Standard/GUID definitions can also be replacements. Only the nearest enclosing modinfo.json owns a source; nested mods are kept separate. Local text GUIDs are classified separately from Standard asset GUIDs.

The [machine-readable register](serp-guid-usage.json) contains every GUID, workspace-relative file/line, definition/reference classification, nearest mod metadata, metadata declarations, source hashes and all cross-folder asset-definition pairs. No existing allocation was changed.
